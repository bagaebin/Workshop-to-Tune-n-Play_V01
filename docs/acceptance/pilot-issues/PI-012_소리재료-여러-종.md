## 관찰 · 기대

사용자 — *"사운드 에셋을 1종만 확인할 수 있고 여러 개를 들어보고 비교할 수 없음."* 기대 — *"여러 종 확인하고 미리 들어본 뒤, 해당 에셋을 연주하는 노트를 작업 영역에 추가."*

## 판단

지금은 설계대로다. 같은 날 주신 소리 재료 명세가 *"재료를 고르는 선택지를 만들지 마. 참여자에게 보이는 소리 재료는 하나뿐"*이라 했고, 예비 2안은 주석으로만 넣었다.

여러 종으로 바꾸면 달라지는 것:

| | 지금 (1종) | 여러 종 |
| --- | --- | --- |
| 화면 | 서랍 슬롯 하나 | 이미지처럼 **소리 패널**이 필요 (썸네일 대신 무엇을 보일지 정해야 한다 — 파형·음표는 명세가 금지) |
| 채택 몸짓 | 슬롯을 끌어 놓기 | 패널의 항목을 끌어 놓기 — **이미지와 같아진다**(PI-010의 혼란이 풀린다) |
| 로그 | `mat.peek {mat:'sound'}` | 어느 것인지 id 필요 — `mat.peek {mat, id}` · 노트에 재료 id · 헤더에 `slots_sound` 셔플 |
| 재료 | 1종 | 지금 3종(본안 + 예비 S2 · G4). 이미지가 5장이면 소리도 5종이어야 진입 비용이 맞는다(K2) |
| 분석 | 소리를 택했나 | 소리 중 **어느 것**을 택했나 — 재료 간 편향 통제(T16과 같은 문제)가 소리에도 생긴다 |

작업량은 반나절 정도다. 걸리는 것은 코드보다 **설계 문서**(D2 · 개발 명세 §3-3 · §6-6 · §10 · §13)와 **일정**이다 — 본 세션이 09.29부터이고 전원이 같은 빌드여야 한다. 이미 진행한 세션이 있다면 그 세션과 조건이 달라진다.

| 안 | 내용 |
| --- | --- |
| A | **그대로 1종.** 소리는 "받은 재료 하나", 비교는 이미지에서만 |
| B | 3종(본안 + 예비 2)을 소리 패널로. 이미지 5 대 소리 3의 불균형은 기록해 둔다 |
| C | 5종으로 맞춘다 — 재료 2종을 더 만들어야 한다 |

결정해 주시면 볼트 개발 명세에 넣을 문장을 먼저 드리고 그 뒤에 구현한다.

## 결정 (09.29) — C · 5종

소리 재료를 이미지와 같게 **5종**으로 하고 **소리 패널**에서 꺼낸다. PI-010(몸짓 불일치)도 함께 풀린다.

### 재료 현황

볼트 `2026-09-29_sound_material/`에 `sound.json`(본안) · `sound_S1.json` · `sound_S2.json` · `sound_G4.json` — **4종.** 하나가 더 필요하다. 저장소에는 본안만 들어와 있고 S2 · G4는 주석 상수다.

### 볼트 개발 명세에 넣을 문장 (제안)

| 절 | 내용 |
| --- | --- |
| §2 상수표 | `SOUND_COUNT` 5 — 소리 재료 수 |
| §3-3 | **소리 패널** — `mat.sound` 슬롯 탭으로 열린다. 이미지 패널과 **같은 자리 · 같은 크기** (160,48)–(360,884). 항목 5개(150 × 100, 순서 셔플), 세로 간격 24. 다섯 항목은 **전부 같은 모양**이다 — 이름 · 번호 · 파형 · 음표 없음. 패널 밖 탭 = 닫힘. 두 패널은 동시에 열리지 않는다(하나를 열면 다른 하나는 닫힌다) |
| §4 | `Note`에 `snd?: string` — 소리 재료에서 온 노트의 재료 id(`s1`…`s5`). `Session.slots`에 `sound: string[]` |
| §5-1 | 히트 테스트 `panel:*`에 소리 패널 항목 `spanel:<id>` 추가 (이미지 패널 항목과 같은 순위) |
| §6-6 표 `mat.sound` 행 | 탭 (열람) — **소리 패널 열기** → `mat.peek {mat:'sound'}` · 패널 항목 **탭 = 그 재료를 1회 재생** → `mat.peek {mat:'sound', snd, dur}` · 패널 항목을 **면으로 끌어 놓기 = 채택** → `mat.adopt {mat, snd, x, y}`(상태가 바뀔 때) + `note.add {src:'material', snd, count}` |
| §10-2 | `mat.peek` · `mat.adopt` · `note.add`에 `snd` 필드(소리 재료일 때) |
| §10-3 헤더 | `slots_sound: ["s3","s1","s5","s2","s4"]` — 셔플 시드는 pid |
| §13 | 소리 — `materials/sound/s1.json` … `s5.json`, 각각 `{ "vals": [...] }` 5–8 이벤트. 길이와 이벤트 수를 비슷하게(진입 비용 균등) |
| §15 G4 | 소리 패널 5항목 · 항목 탭 = 재생 · 끌기 = 채택 · `snd` 기록 · 두 pid에서 `slots_sound`가 다름 |

### 정해 주실 것

| # | 물음 | 기본안 |
| --- | --- | --- |
| 1 | **다섯 항목이 어떻게 보이나** — 이름·파형·음표는 소리 재료 명세 §4가 금지했다 | 다섯 모두 **같은 중립 타일**(서랍의 소리 미리보기와 같은 점 무늬, 움직임 없음). 재생 중인 타일만 밝아진다. 구분은 위치로만 |
| 2 | **항목 탭 = 듣기** — 이미지 패널은 *썸네일 탭 = 아무 일 없음*이다. 소리는 눌러야 들을 수 있으므로 다르게 간다 | 탭 = 1회 재생 |
| 3 | **소리 패널에도 "여기 없다" 슬롯을 두나** | 두지 않는다 — 소리가 없을 때의 길은 마이크와 적기로 이미 있다. 단 이미지 패널과 모양이 달라진다 |
| 4 | **id 매핑** — 어느 파일이 `s1`…`s5`인가 | `s1` = 본안 · `s2` = S1 · `s3` = S2 · `s4` = G4 · `s5` = (추가분) |
| 5 | **적용 시점** — 이미 진행한 세션이 있다면 그 회차는 1종 조건이다 | 헤더 `build`와 `slots_sound` 유무로 구분 |

볼트 개발 명세를 고치고 다섯째 재료를 주시면 `SPEC.md`를 다시 복사하고 구현한다.

## V1.0 적용 (09.29 · R-013)

기능 명세 V1.0 §3 — `mat.sound` 탭 → 소리 목록 → 면으로 끌어 놓기. 목록의 칸 탭 = 들어 보기. 이미지와 같은 몸짓이 됐다. 재료는 볼트에 있는 셋(S1 · S2 · G4)을 넣었다 — 다섯으로 늘리려면 파일 둘을 더하면 된다. 로그 필드 이름은 위 제안의 `snd` 대신 `id`(peek · adopt) · `sound`(note.add).
