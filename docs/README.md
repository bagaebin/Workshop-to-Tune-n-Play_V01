# docs/ — 문서 체계

## 어느 문서가 이기는가

```
볼트 원본 (개발 명세)  ─복사→  SPEC.md  ─절별 메모→  docs/spec/*.md  ─값→  src/constants.ts
```

| 우선 | 문서 | 성격 |
| --- | --- | --- |
| 1 | **[SPEC.md](../SPEC.md)** | 정본. 볼트 *개발 명세*의 복사본. 결정이 끝난 것만 **만들 수 있는 문장**으로 적혀 있다 |
| 2 | 볼트 *구현 명세 V0.3* | 왜 그렇게 정했는가 — 승인 목록 ⑨–㉑ · 대안 · 상위 문서 정정. SPEC과 다르면 **SPEC이 이긴다** |
| 3 | 볼트 *기능 명세 V0.1* | 무엇을 만드는가 — G1–G16 · N1–N5 · 수용 기준 · TODO |
| 4 | 볼트 *결정 기록* | D1–D14 |
| 5 | 볼트 *세션 계획 V03* | Probe가 놓이는 세션 맥락 — 오각 대조 P/O₁/O₂/S/B · 진행자 원칙 |

원본 경로는 [00_sources.md](00_sources.md).

## 이 폴더의 각 하위 폴더가 하는 일

| 폴더 | 무엇을 쌓나 | 갱신 시점 |
| --- | --- | --- |
| [spec/](spec/) | SPEC §1–§14 각 절에 대응하는 **작업 노트**. 절의 범위 · 대응 코드 · 열린 항목 · 구현하며 생긴 메모. 스펙 본문을 다시 쓰지 않는다 | 해당 절을 구현하는 날 |
| [features/](features/) | 기능 명세의 G/N 번호가 SPEC 어느 절 · 어느 파일에 떨어지는지의 추적표 | 파일 신설·절단 시 |
| [acceptance/](acceptance/) | §15 수용 테스트 체크리스트 · §2 ☐ 상수의 파일럿 교정 기록 · §16 진행자 체크리스트 · 파일럿 절차 · **[pilot-issues/](acceptance/pilot-issues/)** 회차별 이슈(하나에 하나씩, 템플릿) | 매일 밤 · 09.26 파일럿 |
| [decisions/](decisions/) | D1–D14 색인(볼트 포인터)과 **저장소에서만 생기는 작은 구현 결정**(R-번호) | 결정이 날 때 |
| [log-schema/](log-schema/) | §10 이벤트 타입 표 · 헤더/이벤트 예시 JSON. `tools/chain.py`의 검증 기준 | 스키마가 바뀔 때 |

## 갱신 규칙

- **값을 바꾸면** 볼트 원본 → `SPEC.md` → `src/constants.ts` 순서. `docs/spec/02_constants.md`에 교정 이력 한 줄
- **SPEC.md는 직접 고치지 않는다.** 볼트 원본을 고치고 다시 복사한다. 동기화 날짜는 SPEC.md 머리말에
- **저장소에서만 필요한 결정**(파일 이름 · 모듈 경계 · 빌드 설정 등)은 `docs/decisions/`에 R-번호로. 설계 결정(D-번호)은 볼트에서만 늘린다
- 볼트 노트를 소스로 만든 문서에 "원본 클리핑" 같은 위치 포인터를 본문 안에 넣지 않는다 — 원본 목록은 `00_sources.md` 한 곳에만
