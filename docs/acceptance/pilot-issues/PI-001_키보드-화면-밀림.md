## 재현

1. 홈 화면 앱으로 실행 → 구간 1
2. 빈 면 슬롯을 탭해 입력 칸을 연다

## 관찰

사용자 보고 — *"모든 인터페이스가 위로 올라가고, 입력창 인터페이스와 키보드만 보임."*
이 회차 로그(`TEST_2026-09-23.jsonl`)에는 `text.open`이 없다 — 적기는 내보내기 뒤에 해 본 것으로 보인다. 로그 근거 없음.

## 기대

SPEC §3-4 — *"입력 칸 1206 × 80, x = 160, `visualViewport` 상단 기준 키보드 바로 위. 작업 면 좌표계 불변(스크롤·축소 없음)."*

## 판단

- 원인 — iPadOS Safari는 입력에 포커스가 가면 그 입력이 키보드에 가리지 않게 **visual viewport를 끌어올린다(pan).** 입력 칸이 포커스 순간 화면 맨 아래(키보드가 올 자리)에 있어 끌어올림이 크게 일어났고, `position:fixed` 캔버스가 같이 밀려 올라갔다
- 고친 곳 — `src/ops/text.ts` · `src/session.ts`
  1. `focus({ preventScroll: true })`
  2. 입력 칸을 **처음엔 작업 면 위쪽**에 두어 끌어올릴 이유를 없애고, 키보드가 뜬 뒤(visualViewport resize) 그 바로 위로 옮긴다
  3. 그래도 pan이 생기면 캔버스를 `offsetTop`만큼 되내려 보이는 자리를 지킨다. 터치 좌표는 캔버스의 실제 rect 기준으로 변환
  4. 키보드에 가려진 자리 판정(`blocked:true`)을 입력 칸의 client rect 기준으로
- 검증 장치 — `text.commit` · `text.abort`에 `pan`(끌어올림 최댓값 px)과 `kb`(키보드 높이 최댓값 px)를 남긴다. `chain.py --pilot`의 `[D1]` 줄에 나온다
