# R-007 — 4단계에서 SPEC이 비워 둔 것들

| | |
| --- | --- |
| 날짜 | 2026-09-22 |
| 상태 | 승인 (구현 기준 · 파일럿에서 재검토) |
| SPEC | §5-1 · §6-4 · §6-7 · §7 · §7-1 · §9 · §11 |
| 코드 | `src/session.ts` · `src/ops/text.ts` · `src/ops/gen.ts` · `src/mic.ts` · `src/lock.ts` |

| # | 빈칸 | 정함 | 왜 |
| --- | --- | --- | --- |
| 1 | 히트 테스트 순서에서 칩 | **칩은 빈 면 슬롯보다 먼저** 본다. 칩은 슬롯 안에 있어 슬롯이 먼저면 영영 맞지 않는다 (§5-1 순서의 유일한 예외) | 칩 100 × 28 × 3은 슬롯 100 × 100을 거의 덮는다 |
| 2 | 칩 탭 | 빈 면 슬롯 탭과 같이 **적기를 연다**. 끌기만 놓기 | 칩 3개면 슬롯 여백이 8 px — 탭할 곳이 없다 |
| 3 | 입력 칸 바깥 탭 | 확정하면서 **그 접촉은 평소대로 동작**(패널과 같은 규칙, R-006 #4) | 닫기 전용 접촉은 로그에 "아무것도 아닌 acted:true"를 남긴다. 파일럿에서 실수 노트가 나오는지 본다 |
| 4 | 규칙·난수 열의 `len` | 탭·누르기 = LEN_DEFAULT, 끌기 = 이동량 (SPEC "LEN_DEFAULT(끌기면 이동량)") · 열을 놓은 뒤 **열 전체가 선택** · 격자 ON이면 첫 on을 양자화 | 소리 재료와 같은 규칙 |
| 5 | 규칙·난수 모드의 접촉 소리 | 누르는 동안 울리지 않고 **뗄 때 열이 놓이며 1회 재생** | 손 모드의 "놓는 즉시 발음"은 노트 하나일 때 얘기 |
| 6 | 슬라이더 기록 | 끌기 중 실시간 반영, **뗄 때 한 번** `rule.param`(값이 바뀐 경우만). step은 [L/32, L/4] 선형, spread 0–1 | 이동마다 남기면 rule.param이 touch.move처럼 는다 |
| 7 | 마이크 노트와 선택 | src:mic 노트는 **선택을 바꾸지 않는다**. `scope`는 그 순간의 선택 값 | 손이 닿지 않은 입력이 선택을 바꾸면 고치기 대상이 갑자기 바뀐다 |
| 8 | 게이트 임계 | 마이크 임계와 **같은 값**을 마스터 출력 RMS에 적용 | SPEC이 별도 값을 주지 않았다. 파일럿에서 게이트 빈도를 본다 |
| 9 | 구간 2에서 `done` 슬롯 | 보이지 않는다. 구간 2는 7분 타이머로만 끝난다 | SPEC §7 — 구간 2 종료는 timer / facilitator |
| 10 | mat=blank 잠금과 새 캔버스 | 구간 2에서 남기고/지우고 새로를 하면 **다시 첫 조작이 채택이어야** 한다. 채택 전 surface 접촉 `acted:false reason:lock`. 목록에서 옛 캔버스로 돌아가면 그 캔버스의 mat 기준 | "구간 2 캔버스의 첫 조작은 채택" — 캔버스마다 |
| 11 | 비상 정지 | 지금 구간을 `seg.end by:facilitator`로 끝내고 **회고 모드로**. 로그·녹음은 남는다. 구간 1에서 멈추면 잠금은 계산하지 않는다 | 데이터를 버리는 정지가 아니라 세션을 닫는 정지 |
| 12 | `lock.apply`의 자리 | `seg.end 1` → **`lock.apply`** → 그로 인한 `gen.set`/`grid.* by:lock` → `snapshot seg` → `canvas.new lock` → `seg.start 2` | 판정이 먼저, 그 결과의 전이가 뒤 |
| 13 | 회고 화면의 자료 | 라이브 카운터 없이 **로그(IndexedDB)에서 계산** — 마킹·미사용·정지(≥ 60 s)·우 4 첫 접촉·잠금 근거 | 복구 뒤에도 같은 답. 계산식이 chain.py와 같다 |
| 14 | 개발 전용 `?fast` | 8 s · 15 s · 10 s로 타이머 단축, 헤더 `dev_fast:true`. 빌드에는 없다 | 15분 타이머를 매번 기다릴 수 없다 (R-004) |
