| 심각도 | **차단 후보** — 사실이면 재료 3종 중 하나가 죽는다(F1 청각 경로) |

| 세션 전 필수 | 예 |

## 관찰

사용자 — *"사운드 에셋 1종이 재생되기만 하고 작업 영역 위에 추가할 수 없음."* 로그 없음.

## 재현 시도

데스크톱 · 같은 빌드 · 세션 P18 — 소리 슬롯에서 면으로 끌어 놓기 2회(슬롯 가운데에서, 진행자 모서리 구역에 걸친 자리에서) 모두 `note.add src:material count 6`. 직전 커밋들은 이 경로를 건드리지 않았다.

## 판단 — 둘 중 하나

| 가설 | 로그에서 보이는 것 |
| --- | --- |
| A. 끌지 않았다 — 이미지처럼 *탭 → 목록 → 고르기*를 기대 | `slot:mat.sound` 접촉이 전부 짧고(`path_len` < 8) `mat.peek`만 있다 |
| B. 끌었는데 안 됐다 — iPad 고유 문제 | `slot:mat.sound`에서 `path_len`이 큰 `touch.up`이 있는데 `note.add src:material`이 없다. 또는 `cancelled:true` |

A면 발견 가능성 문제다 — 이미지는 패널에서 꺼내는데 소리는 슬롯 자체를 끌어야 해서 **두 재료의 채택 몸짓이 다르다**(K2 진입 비용 균등에 걸린다). PI-012와 함께 다룬다. B면 버그다.

## 판정 (09.29 · TEST3)

`TEST3_2026-09-29_3.jsonl` — `slot:mat.sound` 끌기(`path_len 256` · 1.1 s) → `mat.adopt sound` + `note.add src:material count 6`. **iPad에서도 놓인다.** 사용자 확인 — *"소리 버튼을 드래그하면 추가되는 것을 확인. 이미지는 같은 버튼이 메뉴를 여는데 소리는 바로 놓여서 착오가 올 것 같다."*

가설 A다. 같은 서랍의 두 슬롯이 **탭 = 패널 열기(이미지) / 탭 = 듣기 · 끌기 = 놓기(소리)**로 갈려 있다. 소리 재료를 5종 패널로 바꾸면(PI-012 C) 두 재료가 같은 몸짓이 된다.
