## 판단

설계대로다. D4 — 이미지는 변환하지 않고 **그 위에 손으로 친다.** 그래서 몸통 접촉은 작업 면과 같은 노트 입력이고 `image.touch {u, v}`가 함께 남는다. 옮기기는 좌상단 48 × 48, 크기는 우하단 48 × 48 손잡이로 한다.

문제는 손잡이가 **얇은 ㄱ자 선**뿐이라는 것이다. 사진 위에서는 더 안 보인다.

분석 쪽 — 옮기려다 찍힌 노트는 로그에서 가려낼 수 있다: `image.touch` 직후의 `note.add`가 곧바로 지워지거나(`note.remove`), 뒤이어 `image.move`가 오는 경우.

| 안 | 내용 |
| --- | --- |
| A | 그대로. 발견 여부를 파일럿 관찰로 둔다 |
| B | 손잡이를 **눈에 띄게** — 모서리에 반투명 채운 사각형. 글자·아이콘은 없다(N5) |
| C | 몸통 끌기 = 옮기기로 바꾼다 — D4와 충돌(몸통 끌기는 긴 노트 입력이다). 권하지 않는다 |

## 추가 관찰 (09.29 · TEST3)

사용자 — *좌상단이 옮기기, 우하단이 크기라는 것이 계속 헷갈린다.*

로그 — 구간 1의 손 노트 4개(n38–n41)가 **전부 1~4초 안에 지워졌다.** 첫 노트는 이미지 몸통 접촉(`image.touch` → `note.add target_mat image`) 2초 뒤 `note.remove`. 이미지 g3은 크기 조정 직후 옮기기 끌기(`path_len 107`)가 면 밖에서 끝나 `image.remove`. 의도한 조작이 아니었을 가능성이 높다.

표시 보강(안 B)은 볼트 결정 요청의 ④로 올렸다.
