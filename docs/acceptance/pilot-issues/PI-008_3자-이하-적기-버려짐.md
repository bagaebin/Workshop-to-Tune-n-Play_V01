# PI-008 — 세 글자 이하로 적으면 칩이 생기지 않는다 ('테스트')

| 심각도 | **주요** — 참여자가 쓴 글이 말없이 사라진다 |

## 관찰

```
seq 333 text.abort raw '테스트' chars 3 edits 11 dur 5095
seq 337 text.abort raw '테스트' chars 3 edits 11 dur 4295
```

두 번 적었고 두 번 다 칩이 생기지 않았다.

## 판단

이 규칙은 **중도 이탈**(긴 글을 쓰다 포기)을 "안 썼다"와 구분하려는 것이었다(위험 9). 그런데 **한글 세 음절은 온전한 단어**다 — '쿵쿵쿵' · '두둥탁' · '빠르게'. 로마자 3자와 무게가 다르다. 원문은 로그에 남지만 참여자 화면에서는 사라지므로, 참여자는 "안 된다"고 배운다.

선택지:

| | 안 | 잃는 것 |
| --- | --- | --- |
| A | **빈 칸만 abort** (`TEXT_ABORT_CHARS = 0`). 짧은 글도 칩이 된다. 중도 이탈 판정은 분석에서 `chars`·`dur`·`edits`로 한다 | 앱 안의 즉석 구분. 로그로는 그대로 가능 |
| B | 한글은 음절 1 이하만, 로마자는 3자 이하만 abort | 규칙이 복잡해지고 설명하기 어렵다 |
| C | 그대로 둔다 | 짧은 글을 쓰는 참여자의 적기 경로 |

권고는 **A** — 앱은 참여자가 쓴 것을 받기만 하고, 판정은 분석이 한다. 이 연구의 "분류는 입력이 아니라 출력" 원칙과도 맞는다.
