# R-005 — 체류·idle 계산의 세부 (SPEC §10-5의 빈칸)

| | |
| --- | --- |
| 날짜 | 2026-09-22 |
| 상태 | 승인 (구현 기준 · 파일럿에서 재검토) |
| SPEC | §10-5 · §11-1 |
| 코드 | `src/log.ts` `account()` · `tools/chain.py` `dwell_from_log()` |

## 정한 것
1. **활동** = `touch.*` 이벤트와 열린 구간(`play.start→stop` · `mic.span` · `text.open→commit|abort`). 다른 이벤트(전이 · 스냅샷 · facilitator)는 간격을 닫지 않는다
2. **간격의 귀속** — 활동 사이 Δ는 **가장 최근 이벤트의 state**에 더한다. 전이 이벤트는 그것을 일으킨 `touch.up`과 사실상 같은 시각이라 오차는 무시할 수 있다
3. **구간 시작이 기준점** — `seg.start`에서 `lastActivityT = t`. 앞 구간 마지막 접촉부터의 간격은 이 구간의 정지가 아니다. 그래서 *첫 정지*(§15 F1: `seg.start seg:1` → 첫 `touch.down`)가 τ를 넘으면 `idle`로도 남는다
4. **idle의 시각** — `t`는 간격이 **닫힌** 시각(다음 활동), 시작은 `t − dur`
5. **복구** — 이벤트 재생으로 체류·전이 수를 되살리되 idle은 새로 남기지 않는다. 새로고침 전 마지막 접촉 → 복구 후 첫 접촉의 간격은 보통의 규칙대로(τ 초과면 idle, 아니면 체류) 처리한다 — 참여자가 아무것도 하지 않은 시간인 것은 사실이다
6. `T_active` = 구간 1 체류 합. 구간 2는 따로 센다(잠금 판정에 쓰지 않음)

## 검증
`tools/chain.py`가 같은 규칙으로 로그에서 다시 계산해 idle 건수를 대조한다. 4단계에서 `lock.apply`의 `dwell`과도 대조한다.
